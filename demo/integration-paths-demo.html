JusPay Integration PoC

Every button below makes a real call to our deployed App Builder action, which makes a real call to JusPay's sandbox. Nothing here is mocked.

Serve this file over http://localhost (e.g. npx serve from this folder) — opening it directly as file:// can block the network call in some browsers. Also make sure JusPay credentials are saved via the JusPay Config page in Commerce Admin first — there's no .env fallback, so every button below just returns "not configured" until that's done.
Option 1

Hosted checkout (redirect)

● Live call

Creates a real JusPay order and opens their actual hosted payment page. No SDK, no card handling on this page at all.

Option 2

Custom UI, embedded

● Live call

Same session as Option 1 — JusPay's response also includes an iframe link. Embedding it keeps the customer on this page instead of a full redirect.

Step 2

Validate the payment

● Live call

After paying on the link above (or before, to see the "not yet paid" response), this calls our deployed validate-payment action, which asks JusPay's server directly whether the order is really CHARGED. This is the same check Commerce's sales_order_place_before webhook runs before accepting the order.

validate-payment requires require-adobe-auth — paste a Bearer token from an OAuth Server-to-Server credential (see the integration doc, section 5) below. A personal login token will not work.
Option 3

Server-to-server direct

No separate demo

Nothing to click here — Option 1's button above is this pattern already running. The App Builder action holds the API key and makes the real server-to-server call; the browser never sees it. Options 1 and 2 just differ in what happens with the response.

Step 3

Handle the return redirect

● Live call

"Create real JusPay session" above now passes return_url pointing back at this same page. After paying, JusPay redirects the browser back here with order_id, status, and a signature appended to the URL. This page reads order_id from that URL automatically, then calls our deployed payment-status action to re-verify the real status server-to-server — the redirect's own status query param is shown below for comparison, but never trusted on its own.

Not currently on a redirect — pay via Option 1 above and this section fills in automatically when JusPay sends you back.
